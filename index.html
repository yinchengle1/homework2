Generation

Creates initial key material, typically starting with cryptographically secure randomness. BIP-39 represents entropy as words.

Derivation

Computes child keys deterministically from a seed-derived master key and a path. The same inputs produce the same keys.

Encoding & checksum

Hexadecimal represents bytes as text. EIP-55 uses letter capitalization to help detect address typing errors; it does not hide data.

Encoding is not encryption

Hex encoding maps each byte to two hexadecimal characters. It is reversible representation, not encryption. EIP-55 changes capitalization based on the hash of the lowercase address; the underlying 20 address bytes remain the same.

Why not use one algorithm?

Key derivation requires deterministic secret-tree management; elliptic curves provide public/private key relationships and signatures; hashes compress arbitrary-length input into fixed-length digests; checksums help detect mistakes in human-readable strings. These are distinct tasks with different requirements.

What should we expect statistically?

Determinism. Same mnemonic + passphrase + derivation path → same key and address. This is deterministic computation, not fresh randomness each run.

Hash outputs. An ideal 256-bit hash is modeled as uniformly distributed over 2²⁵⁶ outputs. The birthday collision scale is approximately 2¹²⁸ random inputs.

Address space. A 160-bit address has 2¹⁶⁰ possible values. For independently sampled random addresses, birthday collisions become relevant around 2⁸⁰ samples. This is a mathematical scale, not a prediction that ordinary wallets will collide.

Historical timeline

From public-key cryptography to modern wallet standards.

1977
RSA

A foundational public-key cryptosystem supporting encryption and digital signatures.

2001
SHA-2 / SHA-512

NIST published SHA-2 in FIPS 180-2. SHA-512 produces a 512-bit digest and is used by BIP-39's PBKDF2-HMAC-SHA512 seed derivation.

2012
BIP-32

Bitcoin Improvement Proposal defining hierarchical deterministic wallets and child-key derivation.

2013
BIP-39

Mnemonic code for representing entropy and deriving a seed for deterministic wallets.

2014
BIP-44

A multi-account hierarchy and derivation path convention built on BIP-32.

2015
SHA-3 standardized

NIST standardized SHA-3 in FIPS 202, based on the Keccak sponge construction.

2016
EIP-55

Proposed mixed-case checksum encoding for Ethereum addresses.

SHA-2 versus Keccak / SHA-3

SHA-2 and SHA-3 are different hash-function families. SHA-512 belongs to SHA-2. SHA-3 is based on Keccak, but Ethereum's Keccak-256 uses a different padding/domain-separation convention from standardized SHA3-256. They therefore produce different digests for the same input. Keccak was selected for SHA-3 before the standard was finalized in 2015.
